P2 Agent session to implement a story
========================================================================
Complete this one Jira story in ONE Devin session across both
repositories. Do not launch managed/child sessions or competing
implementations. Coordinate both sides against one agreed contract.

1. Verify access to both repos, actual checkout paths, intended
   base branches/HEADs and any existing work. Read applicable repo
   instructions and existing setup/test docs. Treat the Ask plan
   as guidance; check it against the current files before editing.
   If access, required services or a blocking requirement is missing,
   report the exact blocker and stop that dependent work.
2. Give a brief plan tied to AC1/AC2/AC3, then implement without
   waiting for another confirmation if the brief is unambiguous.
   Ask before changing agreed business behavior or expanding scope.
3. Use a feature branch in each changed repo. Reuse existing React
   components/hooks/API clients and Spring DTO/validation/error
   patterns. Keep edits small. Preserve unrelated work. Do not add
   libraries, perform broad refactors or change deployment settings
   unless the task requires it and the scope has been agreed.
4. Keep endpoint, request/response types, nullability, validation,
   error codes and pagination consistent. If the contract changes,
   update its authoritative source and explain compatibility/order.
5. Add or update meaningful tests. First run focused checks, then
   the required repo checks from the documented working directories.
   Use non-watch commands. Inspect failures before retrying. After
   two attempts with the same cause and no new evidence, stop and
   report the cause, attempted fix and next action. Do not relax tests.
6. Start the relevant development services and verify the actual
   React-to-Spring action and its error case in the browser when
   available. Inspect the API response. Capture concise evidence.
   Mark unavailable checks NOT RUN; never substitute a claim of PASS.
7. Recheck the latest relevant diffs and contract in both repos.
   Return an AC-by-AC PASS/FAIL/BLOCKED/NOT RUN table, commands and
   results, branches/commits, files changed and remaining work.
   Follow the Delivery field. Do not merge, deploy or change Jira
   status. Draft a short Jira update for me to review.

Efficiency: follow the relevant code paths; skip generated files
and dependency trees. Do not rerun unchanged passing checks.
Do independent reads/checks concurrently only when supported and
safe within this session; concurrent work is not an ACU guarantee.
Do not promise an ACU cap from this prompt or invent usage figures.

P3 Agent session to fix a bug
========================================================================
Fix one reproducible bug in the selected React/Spring repositories
using one session. Do not start additional sessions.

Jira key/link: [key and URL]
React repo/base: [repo and branch]
Spring repo/base: [repo and branch]
Steps to reproduce: [numbered user actions]
Actual result: [observed symptom and relevant error]
Expected result: [precise behavior]
Environment: [dev/test environment, affected version]
Evidence: [small log excerpt, request/response, screenshot if useful]
Recent relevant change: [commit/PR, or UNKNOWN]
Out of scope: [unrelated changes]
Delivery: reviewable changes first; no push or PR until requested.

Verify the checkouts and repo instructions. Reproduce the failure
and follow the request from React to Spring. Identify the root cause
with file evidence. If reproduction is blocked, report it instead
of making speculative broad changes. Implement the smallest fix,
add a regression test for the failure, and run required checks.
Verify the corrected browser/API behavior and an adjacent error
case. Keep existing contract behavior unless the ticket changes it.
After two failed attempts with the same cause and no new evidence,
stop and report the blocker. Return cause, fix, changed files,
test commands/results, unrun work and a proposed Jira update.

P11 Optional reusable playbook body
========================================================================
Purpose: complete one scoped React/Spring Jira story or bug in one
Devin session and return evidence for review.
Required input: ticket text, both repositories and base branches,
acceptance criteria, scope, known contract source and delivery mode.
1. Validate those inputs and current checkouts; read repo instructions.
2. Establish the shared API behavior, relevant files and existing tests.
3. Ask only blocking questions. Otherwise implement the smallest change
   using existing patterns, with a feature branch per changed repo.
4. Keep both sides of the contract consistent. Preserve unrelated work.
5. Run focused tests then required project gates and actual integration.
6. Stop repeated failures after two attempts with no new evidence.
   Report missing access/services instead of redesigning around them.
7. Deliver one acceptance table, actual test evidence, changed files,
   remaining work and draft PRs only when that delivery was requested.
8. Do not merge, deploy or change Jira status. Do not start child sessions.
Use the session prompt for task details. Mark unverified facts and unrun
checks explicitly. This procedure is not an enforced ACU spending cap.
